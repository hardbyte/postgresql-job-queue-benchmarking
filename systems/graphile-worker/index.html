What this system is built around

Node.js task executors with SQL enqueue, serial named queues and retryable PostgreSQL jobs.

A useful starting point

A natural candidate when Node task executors and SQL-triggered enqueue fit the application. Evaluate the OSS crash-unlock delay and migration workflow against operational recovery targets.

Editorial fit, based on the cited design. Verify against your workload.

Claiming & concurrency

Documented

Named queue jobs execute one at a time. Claim SQL uses FOR UPDATE SKIP LOCKED. This is distinct from global provider rate limiting.

Crash recovery & retries

Qualified

Abruptly terminated OSS workers leave jobs locked for at least four hours; periodic sweeps unlock them. Faster tracked-worker recovery is a proprietary Worker Pro feature.

Failures and crash recovery ↗ Worker Pro scope ↗

Delayed & recurring work

Documented

run_at defers a job; the built-in UTC crontab can backfill missed schedules when configured. Recurring scheduling and eventual execution are distinct.

SQL enqueue API ↗ Recurring task scheduler ↗

Uniqueness / deduplication

Documented

job_key can replace/debounce unlocked jobs; default modes enqueue a new job if the prior matching job is locked. Completed jobs are deleted, so this is not permanent deduplication.

Postgres extension required

Not required

Requirements say pgcrypto is no longer used since v0.13. PostgreSQL 12+ and Node 22.18+ are documented current requirements.
