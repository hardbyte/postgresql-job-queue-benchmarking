Model boundaries & assumptions

This is a deterministic teaching model, not a trace, benchmark, formal proof, or Awa runtime. The playhead counts events; playback speed has no relationship to production timing.

  • One immediately runnable job, two possible workers, successful SQL, healthy maintenance, and enough attempts to retry. Database availability eventually returns.
  • Rescue, backoff, due-job promotion and polling are separate events with compressed waits. Default heartbeat staleness is 90 seconds, with a default 30-second rescue scan; recovery can take longer. Hard deadlines are a separate trigger.
  • The provider either sends on every request or atomically deduplicates a stable operation key across both workers. That deduplication is an explicit provider assumption, not an Awa feature.
  • The lost-claim experiment assumes the enqueue is already durable, storage honors flushes, and the claim is the only unflushed state. It models a local PostgreSQL crash, not arbitrary standby promotion or storage corruption.
  • “Logical database view” collapses ready rows, receipt claims, leases and terminal history. A claim does not physically move one canonical row through these boxes. Closed receipts, lease tokens and cursor evidence enforce the real transitions.
  • The late-worker experiment assumes its original claim survived WAL recovery. It does not model lease identities across a lost asynchronous commit.
  • Priorities, batching, callbacks, unique enqueue conflicts, cancellation, retry exhaustion, DLQ, partitions, capacity and all other production interleavings are omitted. No throughput or metastability claim follows from these examples.
